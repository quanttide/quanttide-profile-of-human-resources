# 全栈工程师绩效标准

> 判定全栈工程师的交付是否有效。绩效记录（report/performance/）按本标准执行。

## 有效性判定

**代码存在不等于交付有效。** 未经过业务验证的代码，无论质量如何，有效性无法认定。

判定有效，三选一：

1. **被使用**：在真实业务流程中运行，产生了业务结果；
2. **被验收**：甲方或负责人按业务流程验证通过，留有记录；
3. **被收编**：进入工程规范，成为后续实现的基准。

代码合入主干、测试通过、文档齐全，都不构成有效。

## 判定阶梯

| 状态 | 定义 |
|------|------|
| 有效 | 通过上述判定 |
| 未验证 | 已交付，无业务验证证据 |
| 未完成 | 期初约定未达成 |
| 已重做 | 交付被负责人重做替代 |
| 滞后 | 测试、文档、规范未随功能跟进 |

## 分项标准

- **服务端功能**：进入 beta 才可判定有效，停留在 alpha 即「未验证」。
- **部署与基础设施**：被后续发布实际使用即有效。
- **测试**：随功能同步交付，缺一个发布周期记「滞后」。
- **文档与规范**：被他人依据执行才算数。

## 期初约定

每期开始前与负责人约定：交付物清单、每项的完成定义、验证方式。

约定缺失的工作项，按判定阶梯从严处理。
